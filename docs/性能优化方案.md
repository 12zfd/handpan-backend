# Render Free 性能优化方案

## 问题诊断

### 实测数据
```
TLS握手: 2.3秒
首次字节(TTFB): 2.6秒
总耗时: 2.6秒（空响应）
```

### 根本原因
1. **Render Free 冷启动**：空闲5分钟后容器休眠，唤醒需要2-3秒
2. **没有对象存储**：每次下载都要从容器磁盘读取
3. **单线程处理**：下载请求阻塞其他请求

## 解决方案

### 方案一：Cloudflare R2 + CDN（推荐）

**效果**：下载速度从 2-3秒 → 0.1秒

**原理**：
- PDF 上传到 R2（Cloudflare 对象存储）
- R2 自动接入 Cloudflare CDN 全球节点
- 用户从最近的 CDN 节点下载，无需经过 Render 服务器

**步骤**：
1. 创建 Cloudflare R2 Bucket（免费）
2. 配置 Render 环境变量（S3_BUCKET, S3_ENDPOINT等）
3. 代码自动切换到 S3 模式
4. 后续所有下载从 CDN 获取

**成本**：$0/月（免费额度足够）

详见：[S3配置指南](./S3配置指南.md)

---

### 方案二：Render Keep-Alive（临时方案）

**效果**：减少冷启动频率，但不能完全消除

**原理**：定时 ping 服务器保持容器活跃

**实现**：
```bash
# 使用 cron 或外部服务每分钟请求一次
curl https://handpan-backend.onrender.com/healthz
```

**工具推荐**：
- UptimeRobot（免费）
- cron-job.org（免费）
- GitHub Actions（免费，需配置）

**缺点**：
- 不能真正加速下载
- 只是避免冷启动
- Render 可能限制这种用法

---

### 方案三：前端缓存优化

**效果**：减少重复下载

**实现**：
```javascript
// 在浏览器 localStorage 缓存 PDF URL
const cachedPdf = localStorage.getItem(`pdf_${scoreId}`);
if (cachedPdf && Date.now() - cachedPdf.timestamp < 24*3600*1000) {
  // 使用缓存的 URL（24小时内有效）
  window.location.href = cachedPdf.url;
}
```

**注意**：
- presigned URL 有时效（默认24小时）
- 适合同一设备重复访问

---

## 推荐组合

**最佳实践**：
1. ✅ 配置 R2（彻底解决下载慢）
2. ✅ 启用 Keep-Alive（减少冷启动）
3. ✅ 前端缓存（减少重复请求）

**预期效果**：
- 首次下载：2-3秒（冷启动）+ 0.1秒（CDN下载）≈ 3秒
- 后续下载：0.1秒（CDN直接从最近节点）
- 同设备重复：几乎瞬时（本地缓存）
